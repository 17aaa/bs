摘要
在传统的项目评审中，学生和老师的申报材料大多采用的是纸质材料，这种
方式会造成资源浪费和管理困难，同时专家进行评审时也是通过纸质化操作，最
终结果的计算也可能会出现人为失误，丧失公平性。随着信息技术飞速发展，项
目管理工作日益复杂化，传统的项目评审方式很难满足当今社会对于高效、 公正、
便捷评审的需求。为此，本文旨在设计并实现一款在线项目评审系统，为专家提
供一个便捷、灵活的评审方式，为用户提供一个高效、公正、透明的项目评审系
统。
在线项目评审系统是一个 Web 系统，它集成了用户上传项目、专家评审等
主要功能，将传统的线下评审的方式转变为线上评审。该系统运用 MinIO 和
MySQL 实现对申报材料的存储和管理，并采用Spring Boot 和Spring Cloud 等后
端开发框架、Element UI 和 Echarts 等前端开发组件成功搭建出了一款基于微服
务架构的在线项目评审系统。
使用一系列的前后端技术栈，开发搭建出一款基于 Web 的在线项目评审系
统。该系统具有定制化评分表、上传项目、专家推荐、评审项目、共享知识库等
功能；具有界面简洁、操作简单等优点。通过该系统，评审成本大大降低、评审
效率显著提高。以便专家有更多的时间和精力去评审项目，用户也能及时得到反
馈，从而迅速的弥补自己的缺陷和不足。

1.1 课题背景
传统的评审方式具有空间限制、成本高、管理不易等缺点，这些缺点可以看
成是线上评审“催化剂”
。随着互联网的飞速发展，新的科学技术不断涌现，这让
项目评审看到了新的曙光。通过互联网技术，人们可以利用一些存储中间件来实
现对数据的长期和便捷管理，从而将专家和管理人员从重复运动中解放，进而提
高项目评审的效率、降低项目的管理成本。在直观感受上，在线评审不仅提高了
评审效率、管理效率，也降低了人力、时间以及资源成本[1]。在线评审作为一种
新型的评审方式，因为其高效、便捷、公正的特点，正在慢慢地改变其在评审模
式中的地位[2]
。在线评审打破了传统评审的地域空间限制、解决了线下需要接待
工作的缺陷，且线上评审无须往来会场、无须面对面交流，这将参会的成本降至
最低[3]
。所以，研发一个安全、稳定、高效的在线评审系统显得尤为重要。
微服务架构是一种新兴的软件架构模式，具有高扩展、高可用的特点，能够
有效应对复杂的业务需求。本课题旨在研究如何利用微服务架构搭建出一款高效、
简约、稳定的在线项目评审系统，以解决传统项目评审方式的不足。
1.2 课题目的
本课题利用信息化技术来分析、设计、开发出一款能够解决传统评审方式不
足的在线项目评审系统，实现一个用户在线上传项目和专家在线评审平台，从而
极大地简化项目申报的流程，为系统用户、管理员以及专家提供便捷的服务[4]
。
除此之外，本系统通过一些加密手段保护学生、老师的个人信息和项目信息，为
项目评审的公平、公正和透明提供保障。因此，开发一个高效的评审系统，对于
提升教育和研究的质量以及推动整个学术界和教育界的进步， 都具有不可估量的
价值。

第3 章 系统分析与设计
3.1 系统需求
本系统设计的目标是将传统的线下现场人工评审转变为在线评审。 在传统的
评审中，学生和老师申报的材料大多数是采用纸质材料，这种方式会造成资源浪
费和管理困难等问题。与此同时评审专家也通过纸质化操作进行打分，最终结果
也可能导致人为失误而丧失公平性。在线评审系统使用自动化流程和电子化材料
提交，允许用户在线上传各类材料，包括图片、文档、压缩包、视频等，这大大
减少了传统评审中的纸质材料处理时间；且在项目被分配给专家的时候，系统可
以通过材料的标签信息等匹配出合适的专家推荐给管理员，管理员也可自行把材
料分配给专家，这样可以提升评审工作的效率和公平性。评审操作是在 Web 界
面上操作，最终分数是各个专家的评分平均值，其通过机器计算，在一定程度上
减少了人为失误等现象。本系统旨在为评审专家提供一个方便、 灵活的评审方式，
为学生、老师提供一个高效、便捷、公平、透明的申报平台。

3.4 系统整体设计
3.4.1 技术体系
本系统使用前后端分离开发模式。 其中，前端技术栈包括 Vue.js、 JavaScript、
CSS、Element UI、Vue-Admin-Template、Axios、Echarts 等。本文利用相关前端
技术栈成功搭建出了一整套前端页面；后端技术栈包括 Java、 Spring Boot、 Spring
Cloud、GateWay、Open Feign、MySQL、MyBatis、Redis、MinIO、Docker 等。
本文利用相关后端技术栈精心构建出了一套高效、稳定的后端系统。
3.4.2 系统架构
本系统采用的是微服务架构。前端使用Axios 传输JSON 格式的数据到后端。
数据首先要经过网关，网关拿到 token 并对其身份进行校验和检查，然后通过路
径将请求分发到各个微服务上面，若微服务部署多台机器，则会进行负载均衡。
所有的微服务和网关需注册到 Spring Cloud Alibab 的Nacos 上。如果其中一个服
务需要调用另一个服务的接口时，需要用到 Open Feign。除此之外，MinIO 用作
文件存储服务、MySQL 用于存储关系型数据、MyBatis-Plus 提供简单方便的数
据库操作、KKFileView 用于文件预览。系统架构图如图 3-12 所示。

第 5 章 总结与展望
5.1 总结
本课题旨在解决传统项目评审过程中的管理、成本、地域问题，为用户提供
方便的项目申报平台、为专家提供便捷的评审方式，也为用户项目的管理提供了
高效的方案。在传统的项目评审过程中，用户需打印纸质材料，这会造成资源浪
费，并且纸质材料过多导致其管理困难； 在专家与用户现场面对面的评审过程中，
需花费大量的人力物力财力规划流程、组织评审会，这对于学生、老师和专家来
说都是不便的。
故本课题针对这一系列问题设计出了在线项目评审系统，使学生、老师能够
随时随地进行材料上传、项目申报、进度查询等，专家能够在任何场景下对项目
进行评审，管理员也能够通过数据库对上传的材料进行高效的组织管理。
本系统的设计使用了前后端分离的开发模式，前端使用Vue、后端则采用微
服务架构，这使得前端和后端可以独立开发和部署，在提高开发效率的同时也增
强了系统的扩展性。
相较于市面上现有的在线项目评审系统，本系统具有以下优点：
(1) 评分标准多样化。管理员可以自行根据类别来定制评分表，使得评审更
具有灵活性。
(2) 匹配专家智能化。系统根据专家的领域和用户申报材料的类别、标签等
进行匹配，使得专家分配更具针对性。
